어제(10월 28일) 샌프란시스코에서 GitHub Universe 2026이 열렸습니다. 같은 날 Tailscale은 주말 내내 시끄러웠던 SSH 취약점 보고서에 대한 패치를 내놨고, 하루 전에는 터미널 에뮬레이터 Ghostty가 1.4.0을 공개했습니다. 셋 다 매일 쓰는 개발 도구라 바로 확인할 만한 소식입니다.

## 1. GitHub Universe 2026: Copilot이 여러 리포지토리를 넘나드는 작업 공간으로

올해 Universe의 메시지는 분명합니다. Copilot을 자동 완성 도구가 아니라 여러 에이전트를 돌리는 작업 환경으로 만들겠다는 것입니다. 개발자 입장에서 눈여겨볼 발표는 다음과 같습니다.

**Copilot 앱의 Projects (공개 프리뷰)**

- 목표를 하나 정하고 리포지토리, 디자인 시안, 채팅 스레드, 회의록 같은 맥락을 붙이면 Copilot이 여러 에이전트를 병렬로 돌려 결과(주로 PR)를 돌려줍니다.
- 여러 리포지토리에 걸친 작업을 한곳에서 추적하는 것이 핵심입니다. 프런트엔드·백엔드·Firebase 함수가 각각 다른 리포지토리에 있는 구조라면 특히 체감이 클 기능입니다.
- Slack, Figma 같은 연결 도구의 내용을 맥락으로 가져올 수 있고, macOS·Windows에서는 승인 후 다른 앱을 직접 조작하는 컴퓨터 사용 기능도 프리뷰로 들어왔습니다. 조직 관리자는 관리 설정에서 이 기능을 끌 수 있습니다.
- 같은 클라우드 에이전트 세션을 앱, VS Code, CLI, 웹에서 이어서 볼 수 있는 세션 연속성도 함께 소개됐습니다.

**GitHub Agentic Workflows 정식 출시**

GitHub Next의 오픈소스 프로젝트였던 Agentic Workflows가 GA가 됐습니다. 이슈 분류, CI 실패 분석, 문서 갱신, 테스트 작성처럼 판단이 필요한 반복 작업을 GitHub Actions 안에서 코딩 에이전트로 돌리는 방식입니다.

- 워크플로를 자연어 마크다운으로 쓰면 일반 Actions YAML로 컴파일됩니다. 그래서 기존 러너 그룹과 정책을 그대로 씁니다.
- `gh aw` CLI 확장으로 다루며, AI 크레딧 사용량을 미리 가늠하는 `gh aw forecast`가 실험 딱지를 뗐습니다.
- 보안 설계가 꽤 보수적입니다. 기본 권한은 읽기 전용이고, 샌드박스 컨테이너와 전용 방화벽 뒤에서 실행되며, 에이전트가 제안한 변경은 적용 전에 별도 위협 탐지 작업이 검사합니다.
- 기본 엔진은 Copilot CLI(이 경우 Copilot 라이선스 필요)지만 다른 코딩 에이전트를 붙일 수도 있습니다. Free, Team, Enterprise에서 모두 쓸 수 있습니다.

**그 밖의 발표**

- **Copilot Fusion**: 작업 성격을 보고 모델을 하나 또는 여러 개 골라 쓰는 멀티 모델 오케스트레이션입니다.
- **Copilot 코드 리뷰 Max**: 기존 Lite, Balanced 위에 더 깊게 보는 등급이 추가됐습니다.
- **GitHub Enterprise에 Copilot 포함**: Enterprise 고객은 별도 Copilot 구독 없이 기능을 쓰고, 쓴 만큼 AI 크레딧을 냅니다. 지금은 영업 채널로만 가능하고 셀프 서비스는 예정입니다.

**주의할 점**: 성능 수치는 모두 GitHub 자체 발표이고, Projects와 컴퓨터 사용은 아직 프리뷰입니다. Agentic Workflows를 도입한다면 처음에는 읽기 전용 작업(분류, 요약)부터 시작하고, `gh aw forecast`로 비용을 먼저 확인하는 편이 안전합니다.

## 2. Tailscale SSH Tailworm: 1.104.4로 바로 올리세요

지난 주말 보안 연구자 Erica Windisch가 Tailworm이라는 보고서를 공개했습니다. Tailscale SSH와 Serve/Funnel 등에서 11가지 문제를 지적한 내용으로, 연구자는 Tailscale에 보고한 지 두 시간 만에 공개해 조율되지 않은 공개라는 논란도 있었습니다.

**무엇이 문제였나**

- 전제 조건은 공격자가 이미 tailnet 안의 기기 하나를 장악했고, 정책상 그 기기에서 대상 서버로 SSH가 허용된 상황입니다.
- 이 상태에서 SSH 포트 포워딩 등을 이용해, 인증된 세션이 설정된 로컬 사용자 권한을 넘어 root 수준으로 올라갈 수 있었습니다.
- Tailscale은 인증이나 접근 정책 검사 자체가 아니라, 인가 이후 권한을 강제하는 부분의 결함이었다고 설명했습니다.

**Tailscale의 대응 (10월 28일)**

- **v1.104.4**에서 SSH 문제와 Serve/Funnel 관련 버그 3건을 고쳤고, 보안 게시판 TS-2026-014부터 TS-2026-017까지 4건을 냈습니다.
- 보고서의 Serve/Funnel 지적 중 2건은 의도된 동작이라고 봤고, 앱 커넥터 관련 지적은 아직 출시 전 기능이라 현재 정식 앱 커넥터는 영향이 없다고 밝혔습니다.

**개발자에게 왜 중요한가**

개발 서버, 홈랩, 사내 스테이징에 Tailscale SSH를 편하게 쓰는 경우가 많습니다. 노트북 한 대가 털리면 접근 가능한 서버의 root까지 넘어갈 수 있었다는 뜻이라 체감 위험이 큽니다.

- Tailscale SSH를 쓰는 모든 기기를 1.104.4 이상으로 올리세요. 서버 쪽 `tailscaled`가 핵심입니다.
- 정책 파일에서 태그나 그룹 단위로 넓게 열어 둔 SSH 허용 규칙을 꼭 필요한 출발지-목적지 쌍으로 좁히세요.
- 민감한 서버에는 추가 인증을 요구하는 SSH check 모드를 고려할 만합니다.
- 공식 글은 headscale을 다루지 않았습니다. headscale을 쓴다면 해당 프로젝트의 공지를 따로 확인하고, 그 전까지는 `tailscaled` 환경 변수 `TS_SSH_DISABLE_FORWARDING=1`로 포워딩을 꺼 두는 완화책이 보도됐습니다.

## 3. Ghostty 1.4.0: 보안 수정 다수, 스크롤백 압축, macOS 27 지원

10월 27일 Ghostty 1.4.0이 나왔습니다. 기능도 많지만 먼저 볼 것은 보안 수정 목록입니다.

**보안 수정**

- 붙여넣기 보호가 캐리지 리턴을 줄바꿈으로 보지 않아, 일부 프로그램에서 확인 없이 명령이 실행될 수 있던 문제를 고쳤습니다.
- 악의적인 Kitty 그래픽 명령으로 크래시, 과도한 메모리 할당, 일부 파일 읽기·삭제가 가능하던 문제가 수정됐습니다.
- 조작된 디렉터리 이름 때문에 zsh 셸 통합이 원치 않는 이스케이프 시퀀스를 보내 클립보드를 몰래 바꿀 수 있던 문제도 막았습니다.
- macOS에서는 조작된 링크를 Cmd-클릭했을 때 위험한 파일이나 URL 스킴이 열리던 문제를 막고, 사용자 정의 스킴은 확인을 거치도록 바뀌었습니다.

신뢰할 수 없는 저장소를 클론하고 그 안에서 셸을 여는 일이 잦은 개발자라면 그것만으로도 업데이트할 이유가 됩니다.

**주요 기능**

- 쉬고 있는 스크롤백을 압축해 텍스트 위주 기록의 메모리를 70~90% 줄였고, 기본 스크롤백 한도는 10MB에서 50MB로 늘었습니다.
- PTY 읽기와 파싱을 별도 스레드로 나눠 macOS 입출력 처리량이 25~55% 올랐다고 합니다.
- `ghostty +ssh` 래퍼가 원격 서버에 Ghostty terminfo를 설치하고, 안 될 때는 `xterm-256color`로 물러납니다. 원격에서 터미널 종류를 몰라 깨지던 문제가 줄어듭니다.
- Linux용 GTK 렌더러가 새로 바뀌어 125%, 150% 같은 분수 배율에서도 글자가 선명합니다. 다만 GTK 4.18과 libadwaita 1.7이 필요해 Ubuntu 24.04 LTS는 별도 작업 없이는 지원되지 않습니다.

**깨지는 변경**

- `copy-on-select` 동작이 바뀌었고, macOS 기본값은 `none`이 됐습니다. 선택만으로 복사되던 습관이 있다면 설정을 다시 확인하세요.
- GTK에서 프롬프트 이동 단축키가 `ctrl+shift+arrow_up` / `ctrl+shift+arrow_down`으로 옮겨졌습니다.
- `scrollback-limit`은 `scrollback-limit-bytes`로 이름이 바뀌었지만 예전 이름도 당분간 동작합니다.

## 마무리

에이전트가 할 수 있는 일이 늘수록, 그 에이전트와 우리가 매일 여는 SSH·터미널이 가진 권한의 경계가 더 중요해집니다. 새 기능을 켜기 전에 권한부터 좁히는 습관이 오늘 세 소식을 관통하는 교훈입니다.
