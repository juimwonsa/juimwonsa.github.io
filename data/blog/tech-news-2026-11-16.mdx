새로운 한 주의 시작입니다. 오늘은 공급망 보안 쪽에서 의미 있는 UI 변화가 하나 있고, React로 조금 엉뚱한 곳에 화면을 그리는 프레임워크가 나왔습니다. Firebase로 Gemini를 쓰고 있다면 3번의 TTS 프리뷰 종료 날짜가 바로 내일이니 먼저 확인해 보세요.

## 1. PyPI, 보안 탭과 출처 경고를 갖춘 프로젝트 페이지 공개

**무엇인가요?**

PyPI가 7월에 예고했던 프로젝트 페이지 개편을 마치고 11월 6일 정식 적용했습니다. 핵심은 새로 생긴 **보안 탭**입니다. 2024년부터 지원해 온 디지털 증명(attestation)이 실제로 있는지를 파일 단위로 보여 주고, 릴리스 사이에 출처가 이상하게 바뀌면 페이지 맨 위에 경고를 띄웁니다. 디자인은 OpenSSF Attestations Style Guide의 권고를 따랐다고 합니다.

**출처 상태와 증명 유형**

- 릴리스의 모든 파일에 지원되는 증명이 하나 이상 있으면 **Full Provenance**, 하나도 없으면 **No Provenance**로 표시됩니다.
- 증명은 두 종류입니다. **PyPI Publish**는 Trusted Publisher가 그 파일을 올렸다는 기록이고, **SLSA Build Provenance**는 파일을 특정 소스 커밋, 빌드 플랫폼, 빌드 절차와 묶어 줍니다.
- 증명 메타데이터는 화면에서 바로 보이고, 투명성 로그로 이어지는 링크도 붙습니다.

**새로 생긴 경고 네 가지**

- **Incomplete**: 같은 릴리스에서 일부 파일만 증명이 있음. 예를 들어 wheel은 Trusted Publishing으로, sdist는 API 토큰으로 올린 경우입니다.
- **Inconsistent**: 한 릴리스 안의 파일들이 서로 다른 저장소나 빌드 시스템에서 나옴
- **Change of Provenance**: 직전 릴리스와 다른 저장소나 워크플로에서 만들어짐
- **Loss of Provenance**: 원래 증명을 붙이던 프로젝트가 갑자기 증명 없이 올리기 시작함

이 밖에 릴리스 파일 탭에서는 파일별 출처 상태를 검색·필터링할 수 있고, 2026년 7월 이전 릴리스 중 최초 공개 후 14일이 지나 추가된 파일에는 경고 아이콘이 붙습니다. 7월부터는 그런 늦은 업로드 자체를 받지 않습니다. 격리(quarantine)된 프로젝트는 다른 배너 없이 격리 배너만 보입니다.

**왜 중요한가요?**

지난 몇 달 이 블로그에서 다룬 공급망 사고 대부분은 "평소와 다른 경로로 올라온 릴리스"였습니다. 탈취한 토큰으로 직접 올리거나, 다른 워크플로에서 빌드한 파일을 끼워 넣는 식입니다. Change나 Loss 경고는 바로 그 신호를 사람이 볼 수 있는 곳에 꺼내 놓습니다. npm에도 provenance 표시가 있지만, 릴리스 사이의 변화를 경고로 따로 띄워 준다는 점이 이번 개편의 차별점입니다.

**주의점**

- No Provenance가 곧 악성이라는 뜻은 아닙니다. 오래된 릴리스나 Trusted Publishing을 안 쓰는 프로젝트에서는 흔합니다. 출처를 암호학적으로 확인할 수 없다는 의미일 뿐입니다.
- 출처 변경도 저장소 이전처럼 정상적인 이유가 많습니다. 경고가 보이면 릴리스 노트나 저장소 활동을 같이 확인하는 습관이 필요합니다.
- Python 패키지를 배포한다면, 한 번 증명을 붙이기 시작한 뒤 수동 업로드를 섞으면 사용자에게 경고가 보일 수 있습니다. 배포 경로를 하나로 정리해 두는 편이 좋습니다.

## 2. Text.js, 브라우저 콘솔에 그리는 React 프레임워크

**무엇인가요?**

Text.js는 브라우저 개발자 도구의 **Console 탭**을 화면으로 쓰는 React 프레임워크입니다. GitHub의 anomalyco 조직이 MIT 라이선스로 공개했고, OpenCode와 연결하는 브리지 패키지도 들어 있습니다. 터미널 UI를 만들 때 쓰는 Ink와 비슷한 방식으로 컴포넌트와 훅을 작성하면, 결과가 콘솔에 문자 격자로 그려집니다.

**어떻게 동작하나요?**

- 레이아웃은 Yoga로 계산해 문자 격자에 배치하고, 한 프레임을 `%c` 스타일 구간으로 압축해 `console.log` 한 번으로 출력합니다. 바뀐 칸이 없으면 아무것도 찍지 않습니다.
- `app/` 아래 파일 기반 라우팅과 공유 레이아웃을 쓰고, `route.ts`로 같은 프로젝트에 API 엔드포인트를 둘 수 있습니다. Next.js App Router에 익숙하다면 구조가 낯설지 않습니다.
- DB 조회가 필요한 페이지는 서버에서 렌더링해 화면을 콘솔로 스트리밍합니다.
- `text run`으로 같은 앱을 터미널에서 돌릴 수 있고, `text mcp`를 켜면 연결된 에이전트가 페이지를 이동하고 키를 누르고 화면을 텍스트로 읽을 수 있습니다.
- VS Code 확장(실시간 미리보기)과 Chrome DevTools 확장(컴포넌트 트리, 프레임 검사기)도 함께 제공됩니다.

시작은 다음과 같습니다. Bun 1.2 이상 또는 Node.js 22 이상이 필요하고, 데스크톱 Chrome, Edge, Firefox, Safari를 지원합니다.

```bash
bunx create-text-app@latest
cd my-app && bun install && bun dev
# localhost:3000 을 열고 개발자 도구 콘솔을 확인
```

화면은 익숙한 React 코드로 짭니다. 아래는 위·아래 화살표로 선택 항목을 옮기는 간단한 예입니다.

```tsx
import { useState } from 'react'
import { Box, Text, useInput } from '@textjs/app'

const items = ['build', 'test', 'deploy']

export default function Page() {
  const [index, setIndex] = useState(0)

  useInput((e) => {
    if (e.key === 'up') setIndex((i) => Math.max(0, i - 1))
    if (e.key === 'down') setIndex((i) => Math.min(items.length - 1, i + 1))
  })

  return (
    <Box className="flex-col border p-1">
      {items.map((item, i) => (
        <Text key={item} bold={i === index}>
          {i === index ? '> ' : '  '}
          {item}
        </Text>
      ))}
    </Box>
  )
}
```

**왜 볼 만한가요?**

서비스 화면을 이걸로 만들 일은 거의 없겠지만, 관리자용 디버그 패널이나 개발 중에만 쓰는 내부 도구라면 이야기가 다릅니다. 페이지 UI를 건드리지 않고 콘솔에서 상태를 들여다보는 키보드 중심 도구를 React로 바로 만들 수 있습니다. 같은 앱이 터미널과 에이전트(MCP)에서도 돈다는 점은, 사람과 에이전트가 같은 텍스트 화면을 공유한다는 요즘 흐름과도 맞닿아 있습니다.

**주의점**

공개된 지 얼마 안 된 프로젝트라 저장소 별 수도 아직 적고, README에 안정성 단계가 따로 적혀 있지 않습니다. 실험용으로 먼저 써 보는 정도가 알맞습니다.

## 3. Firebase AI Logic, Gemini 4 지원과 TTS 프리뷰 모델 종료

**무엇이 바뀌었나요?**

Firebase 릴리스 노트에 지난주 AI Logic 관련 변경이 연달아 올라왔습니다.

- **11월 10일**: `gemini-4-carbon` 지원. Blaze 요금제가 필요합니다. `MINIMAL` 사고 수준, `thinkingBudget`, 명시적 캐싱, 미리 채운 모델 턴은 지원하지 않고, frequency·presence penalty나 candidate count를 넣으면 400 오류가 납니다.
- **11월 11일**: TTS 모델 `gemini-3.8-flash-tts`, `gemini-3.8-flash-lite-tts` 추가. 대신 프리뷰 모델 `gemini-3.1-flash-tts-preview`는 **11월 17일 종료**됩니다.
- **11월 12일**: `gemini-4-hydrogen` 지원. 기본 사고 수준이 `HIGH`이고 `thinkingBudget`과 `XHIGH`, 명시적 캐싱은 쓸 수 없습니다. Microsoft Office와 OpenDocument 파일 입력이 추가됐습니다.

같은 날 Firebase CLI 15.36.0(설정 시 Hosting API 자동 활성화, Authentication 에뮬레이터 시작 속도 개선 등), JavaScript SDK 13.3.0, Admin Node.js SDK 14.5.1도 나왔습니다.

**개발자가 할 일**

- 앱에서 `gemini-3.1-flash-tts-preview`를 부르고 있다면 지금 바로 3.8 계열 TTS 모델로 바꿔야 합니다. 클라이언트 앱에 모델 이름을 하드코딩했다면 스토어 심사 기간 때문에 이미 늦었을 수 있으니, Remote Config로 모델 이름을 내려받는 구조를 고려해 볼 만합니다.
- Gemini 4 모델로 옮길 때는 기존 요청에 넣던 파라미터를 꼭 점검하세요. 특히 Carbon은 지원하지 않는 샘플링 옵션을 넣으면 조용히 무시하는 게 아니라 400으로 실패합니다.
- 12월 1일에는 Gemini 2.5 Pro·Flash 요청이 새 모델로 자동 전환됩니다(11월 10일 글에서 다뤘습니다). 이번 기회에 두 마이그레이션을 한 번에 처리하는 편이 낫습니다.

```ts
import { getAI, getGenerativeModel, GoogleAIBackend } from 'firebase/ai'

const ai = getAI(app, { backend: new GoogleAIBackend() })
// 모델 이름은 코드에 박지 말고 Remote Config 등에서 받아 오는 편이 안전합니다
const model = getGenerativeModel(ai, { model: 'gemini-4-hydrogen' })
```

## 4. OpenAI, 독립 로보틱스 팀 해체

**무엇인가요?**

Fortune이 11월 13일 단독으로 보도한 내용입니다. OpenAI가 별도로 운영하던 로보틱스 팀을 해체하고 인력을 나눠 배치했습니다. 로보틱스 연구 인력은 Mark Chen 최고연구책임자 산하 메인 연구 조직으로, 응용 로보틱스와 하드웨어 팀은 Greg Brockman 사장 산하 Applied 조직으로 옮겼습니다.

**이유는?**

OpenAI 측은 후퇴가 아니라 오히려 로보틱스에 대한 의지라고 설명했습니다. 처음에는 영상 모델 Sora를 기반으로 하는 길이 맞다고 봤지만, GPT-6 Astra 같은 범용 프런티어 모델을 로봇에 바로 붙여도 잘 된다는 것을 확인했다는 것입니다. 보도에 따르면 Nvidia의 시뮬레이션 조작 벤치마크에서 Astra 기반 에이전트가 74.8% 성공률을 기록해, 같은 리더보드의 전용 로봇 모델 최고치 51.0%를 넘었습니다. OpenAI는 자체 휴머노이드를 개발 중이며 2027년 첫 공개 시연을 목표로 하고 있습니다.

한편 비용 압박 속에 "곁가지 프로젝트"를 정리하라는 내부 방침이 있었고, Sora도 이미 접었다는 배경도 함께 전해졌습니다.

**개발자 관점에서**

로봇을 만들지 않더라도 이 결정이 말하는 방향은 분명합니다. 특정 분야 전용 모델을 따로 키우기보다, 범용 모델 위에 도메인을 얹는 쪽으로 무게가 옮겨 가고 있습니다. 다만 인터뷰에 응한 연구자들은 대형 모델이 느리고 클라우드에 있어야 한다는 한계 때문에 기기 안에서 도는 작은 전용 모델은 여전히 필요하다고 지적했습니다. 웹·앱에서도 "큰 모델로 계획하고, 작고 빠른 모델로 실행한다"는 구성이 점점 기본값이 되어 가는 것과 같은 그림입니다.

## 마무리

오늘 소식을 묶어 보면 결국 "보이게 만들기"입니다. PyPI는 릴리스의 출처를, Text.js는 콘솔 속 앱 상태를, Firebase 릴리스 노트는 곧 사라질 모델을 보여 줍니다. 신호는 이미 화면에 떠 있으니, 그걸 실제로 확인하는 습관을 팀의 기본 절차에 넣어 두는 것이 우리 몫입니다.
