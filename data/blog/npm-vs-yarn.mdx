Node.js 환경에서 개발을 시작하면 가장 먼저 마주치는 것이 바로 패키지 매니저입니다. 보통 `npm`과 `yarn` 중 하나를 선택하게 되는데, 과연 이 둘은 어떤 차이가 있을까요?

최근 포트폴리오 사이트를 구축하며 겪은 경험을 바탕으로 두 도구의 차이점을 정리해 보았습니다.

## 1. npm (Node Package Manager)

**npm**은 Node.js를 설치하면 자동으로 설치되는 **기본 패키지 매니저**입니다.

- **장점:** 별도의 설치 과정이 필요 없고, 세계에서 가장 방대한 패키지 저장소(Registry)를 보유하고 있습니다.
- **역사:** 초기에는 속도가 느리고 의존성 트리(Dependency Tree) 관리가 불안정하다는 비판을 받았지만, `package-lock.json` 도입과 버전 업데이트를 통해 성능이 비약적으로 향상되었습니다.

## 2. yarn (Yet Another Resource Negotiator)

**yarn**은 2016년 Facebook(현 Meta)에서 npm의 단점(속도, 보안, 안정성)을 해결하기 위해 내놓은 프로젝트입니다.

- **특징:**
  - **병렬 설치:** 패키지를 한 번에 하나씩 설치하던 npm과 달리, 병렬로 다운로드하여 속도를 획기적으로 높였습니다.
  - **yarn.lock:** 모든 디바이스에서 동일한 패키지 버전을 보장하기 위해 잠금 파일을 처음으로 도입했습니다. (npm도 나중에 이를 벤치마킹했습니다.)
  - **캐싱:** 한 번 다운로드한 패키지는 로컬에 저장해두고, 인터넷 연결 없이도 설치할 수 있게 했습니다.

## 3. 주요 명령어 차이

| 동작               | npm 명령어                 | yarn 명령어              |
| :----------------- | :------------------------- | :----------------------- |
| 패키지 설치 (전체) | `npm install`              | `yarn`                   |
| 패키지 추가        | `npm install [패키지명]`   | `yarn add [패키지명]`    |
| 패키지 삭제        | `npm uninstall [패키지명]` | `yarn remove [패키지명]` |
| 스크립트 실행      | `npm run [스크립트]`       | `yarn [스크립트]`        |

### PnP (Plug'n'Play) 전략

기존 `npm`이나 `yarn v1(Classic)`은 `node_modules`라는 무거운 폴더에 파일을 복사했습니다. 하지만 Yarn Berry는 **PnP** 방식을 도입했습니다.

- `node_modules` 폴더를 생성하지 않습니다.
- 대신 패키지의 위치를 기록한 맵(Map) 파일을 사용하여, Node.js가 패키지를 바로 찾을 수 있게 합니다.
- 덕분에 설치 속도가 비약적으로 빠르고, 용량도 획기적으로 줄어듭니다.

## 결론: 무엇을 써야 할까?

- **개인 프로젝트 / 최신 기술 선호:** **Yarn Berry**를 추천합니다. 압도적인 속도와 디스크 공간 절약은 큰 장점입니다.
- **협업 / 안정성 중시:** 팀원들이 이미 **npm**을 쓰고 있다면 굳이 바꿀 필요는 없습니다. 최신 npm도 충분히 빠르고 안정적입니다.

결국 도구는 도구일 뿐, 상황에 맞는 것을 선택하는 것이 가장 중요합니다. 이번 블로그 구축을 통해 Yarn의 진화를 직접 체감할 수 있었습니다.
