## 1. Python 3.15 정식 출시

10월 9일 Python 3.15.0이 정식으로 출시됐습니다. 이번 버전은 일상적인 코드 작성에 바로 체감되는 변화가 많습니다.

### 눈여겨볼 변경점

- **UTF-8 기본 인코딩 (PEP 686)**: 이제 `open()`으로 파일을 열 때 OS 설정과 관계없이 UTF-8이 기본값입니다. 윈도우에서 한글 파일을 읽다가 `UnicodeDecodeError`를 만나던 일이 크게 줄어들 것으로 보입니다.
- **명시적 지연 임포트 (PEP 810)**: 모듈을 실제로 사용하는 시점까지 로딩을 미룰 수 있습니다. 무거운 라이브러리를 많이 임포트하는 CLI 도구의 시작 속도를 개선할 때 유용합니다.
- **`frozendict` 내장 타입 (PEP 814)**: 변경할 수 없는 딕셔너리가 표준으로 들어왔습니다. 설정값처럼 바뀌면 안 되는 데이터를 다루거나, 딕셔너리를 해시 키로 쓰고 싶을 때 별도 구현 없이 사용할 수 있습니다.
- **`sentinel` 내장 타입 (PEP 661)**: "값이 전달되지 않음"을 표현할 때 관례적으로 쓰던 `_MISSING = object()` 패턴을 대체합니다.
- **컴프리헨션 안의 언패킹 (PEP 798)**: 리스트의 리스트를 평탄화할 때 `[*row for row in rows]`처럼 쓸 수 있습니다.

```python
lazy import pandas  # 실제로 pandas를 사용할 때 로드됨

config = frozendict(host="localhost", port=8080)
flat = [*row for row in [[1, 2], [3, 4]]]  # [1, 2, 3, 4]
```

이 밖에도 전용 프로파일링 패키지(PEP 799), 프리스레디드 빌드를 위한 안정 ABI, 기본으로 켜진 프레임 포인터 등 성능 분석과 확장 모듈 개발 쪽 개선도 함께 들어갔습니다.

### 업그레이드할 때 주의할 점

UTF-8 기본값 변경은 대부분의 경우 반가운 변화지만, 기존에 시스템 기본 인코딩(예: 윈도우의 cp949)에 의존해 파일을 읽고 쓰던 코드가 있다면 동작이 달라질 수 있습니다. 업그레이드 전에 `encoding` 인자를 생략한 `open()` 호출을 한번 점검해 보는 것을 추천합니다.

## 2. Bun, TypeScript를 네이티브 코드로 미리 컴파일하는 AOT 실험 공개

JavaScript 런타임 Bun이 TypeScript/JavaScript를 실행 전에 네이티브 코드로 변환하는 AOT(Ahead-of-Time) 컴파일러 실험 결과를 공개했습니다. `--compile --aot` 옵션으로 제공되며, 런타임을 함께 묶어 실행 파일을 만드는 기존 `bun build --compile`과는 다른 방식입니다.

가장 흥미로운 점은 **TypeScript 타입 정보를 실제 코드 생성에 활용한다**는 것입니다.

- `const port: number = "8080"` 같은 타입 오류는 빌드 단계에서 막힙니다.
- 컴파일 시점에 확인할 수 없는 값, 예를 들어 `JSON.parse()`의 결과는 선언한 인터페이스와 맞는지 런타임에 검사합니다.

지금까지 TypeScript의 타입은 컴파일 후 사라지는 "주석"에 가까웠는데, 이 실험에서는 타입이 실제 실행 동작에 영향을 줍니다. 그만큼 기존 JavaScript의 의미와 달라지는 부분도 있습니다. `as`가 실제 형변환을 수행하고, `x!` 같은 non-null 단언이 런타임에 검사되며, 프로토타입 수정이 제한됩니다. 클래스 인스턴스도 구조가 아니라 클래스 자체로 판별합니다.

아직 실험 단계이고 정식 출시 일정이나 성능 수치는 공개되지 않았습니다. 다만 "TypeScript로 작성한 코드를 진짜 정적 타입 언어처럼 다룬다"는 방향성 자체가 앞으로 JS 생태계에 어떤 영향을 줄지 지켜볼 만합니다.

## 3. Vercel Eve: 디렉터리 하나로 AI 에이전트 만들기

Vercel이 AI 에이전트를 정의하고 배포하는 오픈소스 프레임워크 **Eve**를 공개했습니다(Apache-2.0). Next.js가 파일 구조로 라우팅을 정하듯, Eve는 파일 구조로 에이전트를 정의합니다.

```
my-agent/
├── instructions.md     # 에이전트의 역할과 기본 지침
├── agent.ts            # 모델과 실행 설정
├── skills/             # 필요할 때만 불러오는 절차 문서
├── tools/              # 파일 하나 = 도구 하나 (파일명이 도구 이름)
└── sandbox/sandbox.ts  # 격리 실행 환경 설정
```

`instructions.md` 하나만 있어도 최소한의 에이전트가 동작하고, `tools/` 폴더에 TypeScript 파일을 추가하면 별도 등록 코드 없이 모델이 그 도구를 호출할 수 있습니다.

실무에서 에이전트를 운영할 때 골치 아픈 부분들을 기본 기능으로 넣은 점도 눈에 띕니다.

- **중단 후 재개**: 실행 단계를 저장해 두기 때문에 중간에 끊겨도 이어서 진행합니다.
- **여러 채널 연결**: 같은 에이전트를 Slack, Discord, Teams, 웹 채팅, API에 붙일 수 있습니다.
- **인증 관리**: GitHub, Stripe 같은 외부 서비스 인증을 프레임워크가 대신 처리합니다.
- **승인 게이트와 평가 테스트**: 위험한 도구는 사용자 승인을 기다리고, 배포 때마다 평가 테스트를 돌릴 수 있습니다.

Node.js 24 이상에서 `npx eve@latest init my-agent`로 바로 시작할 수 있습니다. React/Next.js에 익숙한 개발자라면 진입 장벽이 낮은 편이라, 사내 업무 자동화용 에이전트를 실험해 보기에 좋아 보입니다.

## 4. Microsoft MXC: 신뢰할 수 없는 코드를 안전하게 실행하기

AI가 생성한 코드나 서드파티 플러그인을 내 서비스에서 실행해야 할 때, 가장 걱정되는 건 보안입니다. Microsoft가 이런 코드를 격리해서 실행하는 시스템 **MXC(Microsoft eXecution Container)**를 MIT 라이선스로 공개했습니다.

MXC는 독립 서비스가 아니라 **내 애플리케이션에 SDK로 넣어 쓰는 방식**입니다. 앱이 컨테이너 종류, 허용 정책, 실행할 명령을 JSON으로 넘기면 MXC가 요청을 검증하고 적절한 격리 방식을 골라 실행합니다.

- **정책 기반 제어**: 파일 시스템(읽기 전용/읽기·쓰기/금지 경로), 네트워크(프록시, 호스트 필터링), 클립보드나 화면 같은 UI 접근까지 정책으로 제한합니다.
- **플랫폼별 격리 방식**: Windows는 프로세스 컨테이너, Linux는 Bubblewrap, macOS는 Seatbelt를 기본으로 쓰고, 필요하면 마이크로 VM 같은 더 강한 격리로 바꿀 수 있습니다.
- **다양한 SDK**: Rust, .NET, Node SDK를 제공합니다. Node 환경이라면 `@microsoft/mxc-sdk`로 설치할 수 있습니다.

실제로 어떤 접근이 일어나는지 기록해 정책을 만드는 audit 모드도 있는데, 이 모드는 샌드박스 보안을 끄기 때문에 신뢰할 수 없는 코드에는 절대 쓰면 안 된다는 점은 기억해 두어야 합니다. 일부 격리 방식은 아직 실험 단계로 표시되어 있습니다.

## 마무리

이번 주 소식을 관통하는 키워드는 **"더 엄격하게, 더 안전하게"**인 것 같습니다. Python은 인코딩 기본값을 정리했고, Bun은 TypeScript 타입을 실행 단계까지 끌고 왔으며, Eve와 MXC는 AI 에이전트가 할 수 있는 일과 할 수 없는 일의 경계를 명확히 긋는 도구를 내놓았습니다. AI가 코드를 쓰고 실행하는 일이 늘어날수록, 이런 안전장치에 대한 이해는 개발자의 기본기가 되어갈 것 같습니다.
