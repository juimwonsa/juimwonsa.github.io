사내 라이선스 관리 시스템을 개발하던 중, 관리자가 엑셀 파일에 담긴 **수백, 수천 개의 라이선스 키를 한 번에 등록**해야 하는 요구사항이 생겼습니다.

단순히 반복문(`forEach`)을 돌며 DB에 저장하면 될 것 같지만, 여기에는 치명적인 문제가 있습니다.

## 1. 단순 반복문(`forEach`)의 문제점

처음에는 이렇게 생각하기 쉽습니다.

```typescript
// 부적절한 방식 예시
licenseKeys.forEach(async (key) => {
  await db.collection('licenses').add({ key });
});
```

이 방식은 다음과 같은 문제가 발생합니다.

1.  **데이터 정합성 깨짐:** 만약 100개 중 50번째에서 서버가 다운되거나 에러가 나면? 앞의 49개는 저장되고 나머지는 누락됩니다. 어디까지 저장됐는지 알 수 없어 복구가 힘듭니다.
2.  **속도 저하:** 매번 네트워크 요청을 보내기 때문에 데이터가 많을수록 속도가 느려집니다.
3.  **API 호출 비용:** Firestore는 쓰기(Write) 횟수만큼 비용이 청구되는데, 효율적이지 않습니다.

## 2. 해결책: Firestore Batch (db.batch())

Firebase Firestore는 **Atomic Operation(원자성 작업)**을 보장하는 Batch 기능을 제공합니다.

> **Atomic Operation이란?** 모든 작업이 성공하거나, 아니면 **전부 실패(All or Nothing)**하는 것을 의미합니다. 중간에 에러가 나면 아무것도 저장되지 않으므로 데이터가 꼬일 일이 없습니다.

### 실제 적용 코드 (restricted.ts 로직)

제가 개발한 라이선스 등록 모듈(`registerLicense`)에서는 다음과 같이 Batch를 적용했습니다.

```typescript
import { db } from '../config/firebase';

export const registerLicense = async (req, res) => {
  try {
    const { licenseList } = req.body; // 등록할 키 배열
    const batch = db.batch(); // 1. 배치 생성

    licenseList.forEach((item) => {
      const docRef = db.collection('registered_license').doc();

      // 2. 배치에 작업 추가 (아직 저장 안 됨)
      batch.set(docRef, {
        licenseKey: item.key,
        type: item.type,
        createdAt: new Date().toISOString(),
        isUsed: false,
      });
    });

    // 3. 일괄 커밋 (이때 DB에 저장됨)
    await batch.commit();

    res.status(200).send({ success: true, count: licenseList.length });
  } catch (error) {
    console.error('Batch Failed:', error);
    // 에러 발생 시 단 하나의 데이터도 저장되지 않음 (안전!)
    res.status(500).send({ success: false });
  }
};
```

## 3. 주의할 점: 500개 제한

Firestore의 `batch()`는 한 번에 최대 **500개의 작업**까지만 처리할 수 있습니다. 만약 1,000개를 저장해야 한다면 배열을 500개 단위로 쪼개서(Chunking) 처리해야 합니다.

```typescript
// 500개씩 쪼개서 처리하는 유틸리티 예시
const chunks = [];
const itemsCopy = [...items]; // 원본 보존

while (itemsCopy.length) {
  chunks.push(itemsCopy.splice(0, 500));
}

for (const chunk of chunks) {
  const batch = db.batch();
  chunk.forEach((item) => {
    const docRef = db.collection('licenses').doc();
    batch.set(docRef, item);
  });
  await batch.commit();
}
```

## 결론

대량의 데이터를 다룰 때는 속도보다 **'안전(무결성)'**이 최우선입니다. `db.batch()`를 사용하면 네트워크 요청 횟수를 줄여 성능을 최적화할 뿐만 아니라, 예기치 못한 에러 상황에서도 DB를 깔끔하게 유지할 수 있습니다.
