오늘은 지난 25일 글에서 "아직 대기 중"이라고 적었던 Electron 소식의 후속편으로 시작합니다. 데스크톱 앱을 배포하는 분이라면 오늘 바로 할 일이 생겼습니다. 이어서 에이전트 작업 비용을 크게 낮춘 새 모델, 여러 에이전트를 안전하게 병렬로 돌리는 IDE 실험, 그리고 AI 업계 판도를 보여 주는 상장 서류 소식을 골랐습니다.

## 1. Electron 45.1.0·44.10.0·43.8.4: Node.js 24.22.1 반영

### 무엇인가

Node.js가 10월 21일 보안 릴리스(24.22.1 등)로 Brotli 디코더 취약점(CVE-2026-111497) 등을 고친 뒤에도, Electron 정식 버전은 그 직전 버전인 24.22.0에 머물러 있었습니다. 10월 27일 Electron이 지원 중인 세 메이저 라인에 새 정식 버전을 내면서 이 공백이 메워졌습니다.

### 핵심 내용

- **새 버전**: 45.1.0(Chromium 156), 44.10.0(Chromium 152), 43.8.4(Chromium 150) 모두 Node.js 24.22.1을 담았습니다.
- **함께 들어간 수정**: File System Access API의 쓰기 차단 목록에서 `.git/hooks` 경로와 하이퍼바이저 UNC 공유 경로가 빠져 있던 틈이 막혔습니다. 크기 필드가 실제 파일 길이와 맞지 않는 손상된 asar 아카이브 처리, 메인 프로세스와 자식 프로세스 사이의 asar 경로 해석 불일치도 고쳐졌습니다. 릴리스 노트에 별도 보안 섹션은 없지만 성격상 보안과 가까운 수정들입니다.
- **새 기능(45·44)**: `session.registerPreloadScript`에 `matches`, `excludeMatches`, `includeGlobs` 같은 필터 옵션이 생겨, 특정 출처의 페이지에만 프리로드를 붙일 수 있게 됐습니다.
- **그 밖의 수정**: 앱이 시작되는 도중 종료되면 `utilityProcess`의 `exit` 이벤트가 오지 않던 문제, MV3 확장의 이벤트가 백그라운드 서비스 워커에 닿지 않던 문제, macOS `Menu.popup()`이 가끔 뜨지 않던 문제 등이 정리됐습니다.

### 개발자에게 왜 중요한가

Electron 앱은 Node.js를 앱 안에 통째로 넣어 배포하므로, 서버처럼 런타임만 올리는 방법이 없습니다. 이제 패치 버전이 나왔으니 남은 일은 Electron을 올리고, 새로 빌드해서, 자동 업데이트로 사용자에게 퍼뜨리는 것입니다. 메인 프로세스에서 `fetch()`로 외부 응답을 받거나 `zlib`으로 외부 데이터를 압축 해제하는 앱이라면 우선순위를 높게 두는 편이 좋습니다.

```bash
# 사용 중인 메이저 라인의 최신 패치로 올리기 (예: 45 라인)
npm install -D electron@45.1.0

# 앱에 실제로 들어간 Node.js 버전은 메인 프로세스에서 process.versions.node 로 확인
```

### 주의할 점

- 42.x 이하는 지원이 끝나 이번 수정을 받지 못합니다. 이 경우 메이저 업그레이드밖에 길이 없습니다.
- 사용자 PC에 업데이트가 실제로 퍼질 때까지가 노출 기간입니다. 자동 업데이트를 꺼 둔 사용자가 많다면 앱 안에서 업데이트를 권하는 안내를 함께 고려해 보세요.

## 2. OpenAI GPT-6.1 Terra: 화면을 보고 일하는 중간급 모델, 가격은 절반

### 무엇인가

OpenAI가 10월 26일 GPT-6.1 Terra를 공개했습니다. 최상위 모델(GPT-6.1 Sol, GPT-6 Astra)과 경량 모델 사이의 중간급 라인으로, 화면을 이해하고 여러 앱에 걸쳐 동작하는 컴퓨터 사용(computer use) 성능과 속도를 앞세운 모델입니다.

### 핵심 내용

- **사용처**: ChatGPT Work와 Codex에서 Plus, Pro, Enterprise, Edu 사용자에게 배포 중이고, API에서는 `gpt-6.1-terra`로 바로 쓸 수 있습니다.
- **가격**: OpenAI는 표준 API 가격이 이전 GPT-5.6 Terra보다 50% 낮고, 토큰당 비용은 GPT-6 Astra의 10분의 1 수준이라고 밝혔습니다. OpenRouter 표기로는 입력 100만 토큰당 1달러, 출력 5달러, 캐시된 입력 0.05달러이고 컨텍스트는 약 110만 토큰입니다.
- **성능 주장**: 업무용 소프트웨어 사용을 재는 Agents' Last Exam에서 GPT-5.6 Terra를 크게 앞서고, 작업 완료 속도는 평균적으로 GPT-6 Astra와 GPT-6.1 Sol보다 3배 이상 빠르다는 것이 OpenAI의 설명입니다. 다만 깊은 리서치나 복잡한 코딩에는 여전히 Sol이나 Astra를 권하고 있습니다.
- **API 세부**: 개발자 커뮤니티 공지 댓글에 따르면 `reasoning.effort`를 `"none"`으로 두면 `temperature`와 `top_p`를 쓸 수 있다고 합니다. 공식 문서로 확인한 내용은 아니니 직접 테스트해 보는 것이 안전합니다.

```ts
const res = await openai.responses.create({
  model: 'gpt-6.1-terra',
  input: '이 PR의 변경 사항을 세 줄로 요약해 줘',
})
```

### 개발자에게 왜 중요한가

에이전트 비용의 대부분은 "어려운 한 번의 추론"보다 "쉬운 단계의 반복"에서 나옵니다. 화면 읽기, 폼 채우기, 로그 요약처럼 반복적인 하위 작업을 Terra 같은 중간급 모델로 내리고, 설계나 디버깅 같은 핵심 단계에만 상위 모델을 쓰는 라우팅 구조를 짜면 비용과 지연 시간을 함께 줄일 수 있습니다.

### 주의할 점

- 성능 수치는 모두 OpenAI 자체 발표입니다. 내 작업에 맞는 소규모 평가 세트로 기존 모델과 나란히 비교한 뒤 바꾸는 편이 좋습니다.
- 컴퓨터 사용 에이전트는 화면에 보이는 텍스트를 지시로 오인하는 프롬프트 인젝션에 취약할 수 있습니다. 결제나 삭제 같은 되돌릴 수 없는 작업에는 사람의 확인 단계를 남겨 두세요.

## 3. JetBrains ThinkRail: 에이전트마다 git worktree를 따로 주는 오픈소스 IDE

### 무엇인가

JetBrains가 오픈소스 코딩 에이전트 `pi`를 감싼 가벼운 IDE ThinkRail을 GitHub에 공개했습니다. Apache 2.0 라이선스이고 현재 0.x 버전입니다. 자체 모델이나 계정 체계 없이, 사용자가 가진 모델 제공자 인증 정보를 그대로 씁니다.

### 핵심 내용

- **worktree 단위 작업 공간**: git 저장소를 프로젝트로 열고, 작업 공간을 만들 때마다 별도 브랜치와 디렉터리를 가진 `git worktree`가 생깁니다. 편집기, 변경 내역 보기, 터미널, 채팅 세션이 모두 현재 활성화된 worktree에서만 동작합니다.
- **여러 에이전트 동시 실행**: 한 worktree 안에서 여러 `pi` 채팅 세션을 동시에 돌릴 수 있습니다.
- **스펙 그래프**: 모듈 옆에 두는 스펙 파일을 에이전트가 읽고 갱신해, 대화가 끝나도 프로젝트의 의도가 남도록 하는 구조입니다. 현재 IDE에서는 읽기 전용 뷰어로 보여 줍니다.
- **설치와 플랫폼**: macOS(Apple Silicon), Linux(x64, arm64), Windows(x64)용 빌드를 제공합니다. Intel Mac은 소스에서 빌드해야 합니다.

```bash
curl -fsSL https://raw.githubusercontent.com/JetBrains/thinkrail/main/install.sh | bash
thinkrail ~/code/my-repo
```

### 개발자에게 왜 중요한가

에이전트를 여러 개 돌려 본 분이라면 서로의 변경을 덮어쓰거나, 내가 작업하던 체크아웃이 에이전트 때문에 엉망이 되는 경험을 해 봤을 겁니다. ThinkRail의 답은 모델이 아니라 git 자체입니다. 에이전트마다 격리된 worktree를 주고 병합 시점을 사람이 조율하게 만드는 방식은, 이 IDE를 쓰지 않더라도 지금 쓰는 에이전트 워크플로에 바로 가져다 쓸 수 있는 패턴입니다.

### 주의할 점

- 익명 사용 통계(PostHog)가 기본으로 켜져 있습니다. 설정의 Privacy 메뉴나 `THINKRAIL_NO_ANALYTICS=1` 환경 변수로 끌 수 있습니다.
- worktree는 파일 작업 공간을 나눌 뿐 보안 샌드박스는 아닙니다. 같은 사용자 권한으로 도는 에이전트는 다른 경로나 인증 정보에도 접근할 수 있다는 점을 기억해야 합니다.
- 설치 스크립트를 파이프로 바로 실행하는 방식이 꺼려진다면 먼저 스크립트 내용을 확인하거나 소스에서 빌드하세요.

## 4. Anthropic, 나스닥 상장 신청서(S-1) 공개 제출

### 무엇인가

Claude를 만드는 Anthropic이 10월 26일 미국 증권거래위원회(SEC)에 기업공개를 위한 S-1 등록 서류를 공개 제출했습니다. 나스닥 글로벌 셀렉트 마켓에 티커 ANT로 상장할 계획이며, 공모 주식 수와 가격은 아직 정해지지 않았습니다. 주관사로는 Goldman Sachs와 Morgan Stanley가 이름을 올렸습니다.

### 핵심 내용

Yahoo Finance가 정리한 서류 내용은 다음과 같습니다.

- **매출**: 2026년 상반기 매출이 163억 달러로, 2025년 한 해 매출 46억 달러를 크게 넘었습니다.
- **손실과 지출**: 6월까지 순손실은 807억 달러인데, 대부분은 회계상 비용이라고 합니다. 상반기 AI 인프라 지출은 90억 달러였습니다.
- **컴퓨팅 계약**: Amazon, Google 등과 확정된 클라우드 컴퓨팅 계약 규모가 4,300억 달러를 넘습니다.
- **고객 집중도**: 매출의 약 5분의 1이 두 고객에게서 나왔습니다.
- **위험 요인**: 모델이 예상하지 못한 능력을 갖게 될 가능성, 미국 수출 통제 지시로 일부 모델 접근이 제한된 일, 미 국방부와의 분쟁 등이 적혀 있습니다.

### 개발자에게 왜 중요한가

Claude API나 Claude Code를 쓰는 팀에게 상장 자체가 당장 무언가를 바꾸지는 않습니다. 하지만 이런 서류는 평소 볼 수 없던 공급자의 사정을 숫자로 보여 줍니다. 컴퓨팅 비용과 매출 구조, 소수 대형 고객 의존도, 규제 위험이 결국 앞으로의 API 가격과 정책, 모델 제공 범위에 영향을 줍니다. 수출 통제로 특정 모델의 접근이 막힐 수 있다는 내용은 특정 모델 하나에 서비스를 묶어 두는 것이 왜 위험한지 보여 주는 사례이기도 합니다.

### 주의할 점

- 위 수치는 언론 보도를 거친 것이며, 정확한 기준과 회계 처리는 SEC에 올라온 원문 서류에서 확인해야 합니다.
- 서류는 아직 효력이 발생하지 않았고, 상장 일정과 조건은 바뀔 수 있습니다.

## 마무리

오늘 소식을 관통하는 주제는 "의존성의 비용"입니다. Electron 앱은 Node.js 수정이 런타임 공급자를 거쳐야만 사용자에게 닿고, AI 에이전트는 어떤 모델과 어떤 공급자에 얼마나 기대느냐에 따라 비용과 위험이 달라집니다. 패치 경로를 짧게, 모델 교체 비용을 낮게 유지하는 구조가 결국 가장 좋은 보험입니다.
